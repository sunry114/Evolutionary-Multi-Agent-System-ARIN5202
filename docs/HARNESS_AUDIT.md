# Harness 功能核查与现实任务边界

核查日期：2026-11-19（UTC+8）。范围包括默认 provider Harness、共享工具 broker、
审批和恢复、Docker 执行、交付证据，以及 baseline / Claude Code 适配器的回归。

## 本次失败与修改

此前一次失败任务的检查点记录 43 次模型请求、23 次工具调用，最后三次为
`invalid_action`，并非此前的 8192 token 输出截断。历史记录未保存这些动作的
具体字段，无法从旧记录判断缺失的具体字段。运行过程中出现了大量格式拒绝、
局部修复时反复重写文件，以及多次读取完整文件。

本次不提高连续失败上限或放宽工具权限，而是补齐执行协议和工程工具：

- DeepSeek 执行阶段使用原生函数调用，以函数 schema 表达工具参数；每轮只接受
  一个已注册调用。终止操作为 `finish_task` / `report_blocker`，不是可执行的自由文本。
  未知函数、多函数、截断或非法参数回复被拒绝，且不执行部分动作。
- HKGAI 和既有测试 provider 继续使用 JSON 动作协议。规划、群聊等文本接口保持兼容。
  `run_config.execution.decision_protocol` 和检查点记录所用协议。
- `edit_file` 只替换唯一的完整匹配；匹配不存在或有歧义时原文件不变。
- `read_file` 支持 1 起始的 `start_line` 与 `max_lines`；`search_files` 提供字面量查询、
  文件路径、用途和行号；`check_python` 编译检查语法但不导入或执行程序。
- 模型上下文缩短旧写入内容及旧大输出，保留最近四次完整工具结果、失败退出码、
  当前成果摘要和动作状态；完整检查点证据不因模型上下文压缩而被修改。
- 无效动作区分缺少类型、未知工具、参数不是对象等原因；无效原生调用也记录
  安全的校验类别。连续失败计数和反馈跨审批恢复保存，成功动作重置连续计数。
- Docker 保留 `-I`、无外网、非 root、只读根文件系统等限制，通过可信启动器只将
  容器内的脚本目录与 `/workspace` 加入模块搜索路径。修复了多文件测试无法导入
  同工作区模块的问题，不将项目代码改为在主机执行。
- Python 执行审批除脚本摘要外绑定工作区输入摘要，覆盖源码、配置、数据文件和
  目录变化；不包含 `.git` 与 broker 临时文件。输入快照上限为 32 MiB、1024 文件、
  128 目录、32 层。源码依赖变化需要新审批，旧审批不会授权执行新版本。
  旧版本仅绑定脚本的待执行审批会要求重新确认，不静默扩大授权范围。
- Python / Git 容器清理失败会传播为 `cleanup_failed` 并隔离任务；运行结果不确定时
  不再作为普通可恢复错误继续调用工具，须先人工核对和清理。

原生函数调用请求格式参考 [DeepSeek 官方接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)。
原生协议仍不能保证模型每次产生正确参数，因此保留本地校验、有限重试和预算。

### 重复已完成动作导致 platform_tool_error

随后一次 QA 运行已获批并成功执行 Python，模型又对完全相同的脚本和工作区输入
请求执行。审批去重返回已消费的审批，领取时发生冲突，被外层误归类为
`platform_tool_error`。只读核对确认脚本摘要、工作区摘要均与已完成动作一致。

现在执行器用明确的 `ActionAlreadyCompleted` 区分已知完成结果与运行中/未知结果。
模型发起相同动作时，broker 返回持久化结果并标记 `replayed:true`；若检查点保留
原始输出，同时恢复该输出供模型判断。不会再次执行工具、再次消费许可或自动
批准新动作。失败测试同样返回原失败证据，修复源码后仍需新审批。
显式重放旧审批检查点仍被拒绝；运行中或结果未知的动作仍停止等待核对。

未预期异常新增 `platform_tool_exception` 记录安全的工具名称和异常类别，
不保存异常正文；不确定的执行结果继续保留 `inflight` 恢复保护。
回归覆盖实际重复请求路径、失败后修复再审批、旧检查点重放拒绝、并发消费，
以及真实 Docker 中同一批准动作只执行一次。

## 能力与验证范围

### 重复观察与任务推进

后续 `turn_limit` 记录显示 88 轮模型请求、66 次工具调用，其中列目录 38 次、
读取文件 19 次、语法检查 4 次、Python 调用 4 次、写文件 1 次。写入源码后
持续观察相同输入，最终没有产生要求的 `report.md`。

现在原生协议在受限大小内以配对的 assistant function call / tool result 消息
重放最近四次真实完成的调用，同时保留当前目标、完整动作状态摘要和交付要求。
这使模型明确看到自己已经做过什么，而不只是每轮重新接收一份独立用户 JSON。
历史消息副本最多 64 KiB，不改变原始持久化证据。

`ProgressGuard` 按工作区输入版本、工具名称和规范化参数统计重复动作。
目录、文件范围、文件搜索、语法检查、无变化写入及测试结果复用等相同动作
在同一版本下观察两次后，再次提出时会被抑制，不实际调用工具或扣工具次数；
模型轮次仍计入原有预算。成果列表还绑定当前可见成果版本，新共享成果出现后
允许重新查询。源文件变化、外部编辑、分段追加和不同读取范围均可重新检查。

抑制后给出明确的实现、修复、测试或交付提示，并在下一轮暂时移除正在空转的
工具；之后恢复可用，必要的其他检查保持开放。模型上下文另外显示剩余轮次、
必需交付路径及其是否已登记。统计跨审批恢复保存，无法安全计算输入摘要时
停用该次抑制，避免妨碍排查本身。

若模型连续六次无视恢复反馈、继续重复已观察动作，运行会明确返回停滞阻塞，
保留证据供核对，不以“读过文件”判成功。现有轮次、工具预算、审批和独立交付
验证保持有效；这个保护不能保证任意模型或任意任务都能完成。

真实恢复验证使用空临时状态和固定合成报告任务：测试驱动先注入三次列目录，
第三次被抑制；随后真实 DeepSeek 用两次请求完成写文件和终止，根任务成功。
共 5 轮模型循环、3 次实际工具调用、1 次重复抑制。回归另外覆盖长文件多范围
读取、模型请求期间外部修改、正常重复分段追加、审批恢复后的计数，以及
持续停滞时不会伪造成功。

## 真实场景与验收

使用临时空状态、固定合成库存模块和固定测试脚本，未发送真实任务、群聊或记忆：

1. 模型定位错误乘法函数，使用 `search_files`、`read_file`、`edit_file` 修复源码。
2. `check_python` 检查语法，`run_python` 产生审批请求，执行器暂停。
3. 测试驱动只批准原样保留的固定 `verify.py`；恢复后在真实 Docker 中执行。
4. 正常值、零值、小数三项测试全部通过，退出码为 0。
5. 模型生成交付说明，平台读回并核对最终文件，根任务成功。

额外回归覆盖模糊编辑不改文件、路径和软硬链接拒绝、取消后的迟到写入、
工具清理失败隔离、第三次有效回复恢复、旧上下文不污染原始证据、源码变化
使审批失效，以及同一测试脚本对新依赖版本重新申请审批。

真实模型合成场景另行运行，使用当前 DeepSeek 配置、真实审批状态和真实 Python 容器。

## 是否覆盖“大部分现实任务”

可以支持常见文本交付、CSV/JSON 文本处理、Python 标准库脚本、较小的多文件
Python 项目、带原生 HTML/CSS/JS 的轻量 Web 应用，以及需要文件交接的串行协作。
完整功能仍取决于任务要求、模型输出质量、运行预算、可用数据和人工审批。
不能据这些验证宣称它已经是通用开发环境或适用于大部分不受约束的现实任务。

现阶段明确不具备：Node/npm 或任意依赖安装、任意 Shell、浏览器交互/截图验收、
办公二进制文档转换、长期服务部署、任意私有 SaaS 接入，以及大规模代码库无限制处理。
生成 JS/TS 文件不意味着可以执行、构建或测试 Node 项目；源码检查不意味着
UI、性能、并发或业务完整性已被验证。本次没有为覆盖这些领域而改变网络、
运行时或审批边界。

部署修改需要重启 Web 服务。失败历史保留；本次没有修改旧任务状态、自动重跑
真实用户任务、发布服务或推送 Git。当前失败保护仍可能在真实模型持续不配合时
停止任务，但日志能够区分协议错误、输出截断、预算、执行环境和交付问题。
